# tasks-tui v1.1: polish — design

**Status:** implemented on branch 2026-09-14 (plan docs/plans/2026-09-14-tasks-tui-v1.1-polish.md). Goal: tui-7ce28f. Supersedes the row, table, legend, and selection paragraphs of `2026-09-13-tasks-tui-v1-design.md` §5 and §8.3 where the two differ.

## 1. Problem

v1 renders every table with literal widths: `pad(prefix, 8)`, `pad(name, 4)`,
`pad(id, 12)`, `pad(status, 10)`. A project named `natural-systems-v2` pushes its
counts out of their columns; the counts are left-aligned strings, so `0` and `28` do
not line up under their headers; the Projects table takes 5/9 of the width whatever
its content, leaving a gap before the pane. Task rows append their marks (`⟳ 30d`,
`◆ owner`, `⏸ user`) after the tags, so the eye has to scan each row to find them.
Selection is full reverse video; the key legend is a hard-coded string at the top
left; nothing on screen moves while a load is in flight; `q` is swallowed by the
picker and confirm overlays; `enter` is the only key that opens a row.

v1.1 replaces literal padding with a measured column model, gives every view one
visual language — an accent gutter, a tinted selection, a right-aligned hint — and
fixes the keys. It adds no commands, no config keys, and no new data from `tasks`.

## 2. Decisions

- **A column model of our own, not `lipgloss/table`.** `internal/ui/columns.go` is
  a measured grid: each column has an alignment and a minimum width, at most one
  column is flexible, widths are the widest cell over *every* row so scrolling never
  shifts a column, and columns drop in a declared order when the terminal is narrow.
  Rejected: `lipgloss/table` — it owns the grid, borders, and wrapping, and a
  per-row tinted selection under per-cell styles fights it; the views keep
  rendering rows themselves.
- **Marks are a glyph column, not a trailing note.** A fixed four-cell column
  between age and title holds `◆`/`◇` (claim), `⏸` (park), `⟳` (periodic), and `▸`
  (goal with open descendants), each in its own cell so a glyph always lands at the
  same offset. The detail each glyph summarises — owner, `user`/`agent`, the cadence,
  the open count — stays after the tags in the same semantic colour, so colour ties
  the detail to its glyph. Rejected: a right-aligned trailing column — tags are ragged
  and the column would float with them; and leaving marks where they are — the
  alignment the person asked for is the point.
- **Selection is a tinted row with an accent cursor, not reverse video.** A new
  `identity.Surface(slot, tone)` is the slot's hue at low lightness and half
  saturation: the row's background, with `▌` in the accent in a two-cell gutter that
  every row carries blank. Reverse video inverts the priority and status colours a
  row was carrying; a surface keeps them legible. `Surface` is the TUI's own anchor,
  not one of familiar's ramp stops; §8.2 of v1 names the anchors that are.
- **The legend is generated from the keymap.** `keys.go` declares groups of
  `key.Binding`; the panel renders their `Help()` values, so a binding without help
  text is a test failure and a new key cannot be forgotten in the legend.
- **No new configuration.** Widths, the pane cap, and the fade thresholds are
  decided here. A person who wants them tunable files an idea.

## 3. The column model

```go
type align int             // alignLeft, alignRight
type column struct {
    key   string           // names the column in tests and in the drop order
    label string           // the header text; "" for a structural column
    align align
    min   int              // never narrower; a test asserts 1 <= min and min >= lipgloss.Width(label)
    flex  bool             // takes the remainder; at most one per table
    drop  int              // 0 never drops; otherwise higher drops first
}
type span struct {
    text  string           // plain text; width is lipgloss.Width(text)
    style lipgloss.Style
}
type cell struct {
    spans []span           // rendered in order; the cell's width is the sum of theirs
    tail  []span           // flexible column only: appended after spans, two cells apart
}
type table struct {
    cols    []column
    gap     int            // cells between columns; 2 everywhere
    flexMin int            // the least the flexible column's spans keep; 24 for task rows
}
func (t table) minWidth(rows [][]cell) int               // the drop-0 columns as measured, their gaps, and flexMin
func (t table) widths(rows [][]cell, width int) []int    // 0 marks a dropped column
func (t table) header(widths []int, s *Styles) string
func (t table) row(widths []int, cells []cell) string
```

A cell is a list of styled spans, so the marks column is four one-cell spans and
the flexible cell is the title span with the tags and details as its tail. `widths`
measures each non-flex column as `max(min, widest cell over all rows)`, summing the
spans and ignoring tails, then sums the columns with their gaps. While the sum plus
`flexMin` exceeds `width`, it zeroes the remaining column with the highest `drop`
(so `proc` goes before `cx`, `cx` before `sz`, and `age` last). When every droppable
column is gone and the sum still exceeds `width`, the flexible column gets whatever
is left, down to zero, and the row is clipped at `width` by the caller's `MaxWidth`;
a table with no flexible column clips the same way. Nothing is ever hidden by a
rule the model does not state: `minWidth` is the width below which clipping starts
for the rows given, and callers that decide layout (§5) ask it rather than carrying
a literal.

`row` renders each cell's spans, pads to the column's width on the side its
alignment leaves free, and joins the columns with `gap` spaces. A flexible cell
renders as `spans  tail[0]  tail[1] …`; when that exceeds the column, the spans are
truncated with `…` (`ansi.Truncate` over the styled string) down to `flexMin`, and
only then is the tail truncated from its end. Dropped columns render nothing, not
a blank. The header renders every non-dropped column's `label` in `Muted`, aligned
like its cells; a blank label is blank cells, so `gutter` and `marks` keep their
two and four cells under the header.

Width and truncation use `lipgloss.Width` and `ansi.Truncate` from
`github.com/charmbracelet/x/ansi`, already a transitive dependency; both count
grapheme width, so `⟳` and `⏸` measure as the terminal draws them.

## 4. Task rows

Every task list — the project view's tabs and the pane on the Projects view —
renders through one `table`:

| key | label | align | min | drop | cell |
|---|---|---|---|---|---|
| gutter | | left | 2 | 0 | `▌ ` in the accent on the selected row; blank otherwise |
| id | `id` | left | 2 | 0 | accent |
| prio | `P` | left | 2 | 0 | `P<n>` in the priority colour; blank for a parked row without one |
| size | `sz` | left | 2 | 2 | muted |
| cx | `cx` | left | 4 | 3 | muted |
| proc | `proc` | left | 7 | 4 | muted |
| status | `status` | left | 6 | 0 | the status style; `doing` in the accent; `unresolved` for an unresolved parked row |
| age | `age` | right | 3 | 1 | base when under a day (`now`, `Nm`, `Nh`); muted for `Nd` and `Nw` |
| marks | | left | 4 | 0 | four one-cell spans, one glyph or a space each, see below |
| title | `title` | flex | 24 | — | spans: the title in the status style; tail: `[tags]` muted, then the details |

The marks cell is four fixed positions: `◆` accent when the claim is live, `◇`
muted when stale; `⏸` yellow when waiting on the user, muted on the agent; `⟳` teal
for a recurrence; `▸` muted for a goal with open descendants. An absent mark is a
space, so `⟳` sits in the third cell of every row that has one.

The tail after the tags, each piece in the colour of its glyph: the claim owner,
`user` or `agent`, the cadence (`30d`), and `N open`. A parked row in the pane keeps
its `→ next step` line beneath it, indented to the title column.

The project view gains a header row above the list; its footer shows the filter
and its matches while one is active (`/hook · 3 of 20`) and otherwise disappears,
since the active tab now carries the count (§6).

## 5. The Projects view

The table:

| key | label | align | min | drop | cell |
|---|---|---|---|---|---|
| project | `project` | left | 7 | 0 | `▌ ` accent bar then the prefix in bold |
| name | `name` | left | 4 | 1 | the root's basename, muted |
| doing | `doing` | right | 5 | 0 | accent when non-zero, muted when zero |
| todo | `todo` | right | 4 | 0 | base when non-zero, muted when zero |
| idea | `idea` | right | 4 | 0 | base when non-zero, muted when zero |
| blocked | `blocked` | right | 7 | 0 | red when non-zero, muted when zero |
| activity | `activity` | right | 8 | 0 | age, faded as §4 |

There is no flexible column and no gutter: the accent bar is each row's identity,
and the selected row is marked by its surface tint alone. An unreachable project
renders the bar and prefix in muted, then `✗ unreachable`
across the remaining columns.

Layout is decided from the two tables' own numbers, never a literal. The Projects
table takes its measured width. The pane is drawn only when what remains after the
table and a one-cell muted `│` is at least the task table's `minWidth` over the pane's rows (58 cells
with `tui-` ids, more for a longer prefix); otherwise there is no pane and the table has the whole
width. At that width the Projects table drops `name`, and below its own `minWidth`
(about 48 cells) its rows clip at the right edge. The pane's `ready` section stops
at eight rows as before, and the line after them reads `N ready · 8 shown` in muted.

The strip below stays: `9 doing · 15 parked across 20 projects`.

## 6. The project view

The header keeps the accent bar, prefix, and root; the four counts become muted
chips with the same non-zero colouring as §5.

Tabs: the active tab is a pill — the accent as background, the tone's contrasting
text (`#101010` on a dark tone, `#fafafa` on a light one), one cell of padding each
side — carrying the count of rows it shows, ` 1 Ready 20 `, which is the filter's
matches while one is active. Inactive tabs are muted text. While a load is in
flight the count is the last one loaded; a tab never shows a count it has not seen.

Empty states name the list and offer a key in muted: `nothing ready — a adds a
task`, `nothing doing`, `no open tasks`, `no ideas — a then ? files one`,
`nothing done yet`. A filter with no match reads `no rows match /<filter>`.

## 7. Colour

`Styles` gains:

| name | use |
|---|---|
| `Surface(slot)` | selected-row background: the slot's hue, saturation × 0.5 × satScale, lightness 20 dark / 92 light |
| `Gutter(slot)` | `▌` in the accent over the surface |
| `Pill(slot)` | accent background, contrasting text |
| `Rule(slot)` | the accent for the overlay rule of §9 |
| `Recent` | the base foreground for ages under a day |

The pill text pair joins §8.3's table of hard-coded colours; nothing else is added.
Zero counts, stale claims, agent parks, `Nd`/`Nw` ages, and inactive tabs all use
`Muted`, so one dim tone carries "nothing to see here" across the app.

## 8. Status line and notices

The status line is two halves: crumbs on the left (`projects › ops › ops-d34aad`),
`? keys` right-aligned. While the top view's loader is in flight a
`bubbles/spinner` (`MiniDot`) in the accent replaces the first crumb's separator
position; the App ticks it only while `top().loading()` is true, a new method on
`view`. A notice replaces the crumbs, prefixed by its level glyph: `✗ ` error in
red, `⚠ ` warning in yellow, `· ` info in muted; the hint stays on the right. The
message log shows the same glyphs.

## 9. Overlays and the legend

Every bottom overlay — prompt, confirm, picker, quick add — draws a rule of `─`
across the width in the current project's accent (muted when no project is
current) above its title line, so the overlay reads as a layer over the view. The
picker's selected item uses `Surface` and the accent instead of reverse.

`?` opens the legend as a centred panel: `lipgloss.Place` over the body, a rounded
border in muted, padding `1 2`, the title `keys` in bold. Inside, four groups side
by side with four cells between them, each a header in muted and rows of `key`
(bold, right-aligned within the group) and its help text:

| move | open | task | app |
|---|---|---|---|
| j/k, g/G, pgup/pgdn, tab/shift+tab, 1–5 | enter/i open, esc back, / filter, r reload | a add, l launch, s start, p park, d done, x drop, y copy id | ? keys, W messages, S sort, q quit or close |

The groups are declared in `keys.go` as `[]key.Binding` slices; the panel renders
`Help().Key` and `Help().Desc`. A binding in a group without help text fails a test.
When four groups side by side are wider than the terminal, they are laid out two
by two; when two are still wider, they stack. The panel's content lives in a
`bubbles/viewport` sized to the body; when the content is taller than the body the
panel is placed at the top rather than centred, `j/k` and the page keys scroll it,
and a muted `↓ more` sits on its bottom border while lines remain below. The App's
legend handling gains the scroll keys it already gives the log.

## 10. Keys

- `q` closes the legend, the log, the picker, and the confirm overlay. From a bare
  view it quits, as before. Inside a text prompt it is text.
- `i` opens the highlighted row, beside `enter`, in both list views. The `Enter`
  binding gains the key; its help reads `enter/i open`.
- Everything else is unchanged.

## 11. Testing

- `columns`: widths are measured over every row, not the visible window, summing a
  cell's spans and ignoring its tail; every column's `min` is at least its label's
  width; the header minimum holds when cells are shorter and a blank label keeps its
  cells; right alignment pads on the left; columns drop in `drop` order and dropped
  columns render nothing; below `minWidth` the flexible column shrinks to zero and
  the row clips instead of panicking; a flexible cell truncates its spans to
  `flexMin` before touching the tail, and truncates the tail from its end after; a
  row with `⟳` and one without put the title at the same offset.
- `rows`: the marks cell places each glyph in its fixed position with and without
  its neighbours; the tail carries the owner, waiting-on, cadence, and open count in
  their colours; ages under a day are base and older ones muted.
- `projects`: with prefixes of length 2 and 18 the counts of every row start at the
  same column; zero counts are muted and non-zero `blocked` is red; the pane is
  omitted when the remainder is under the task table's `minWidth` and the table
  takes the width; at 48 cells `name` is dropped and rows clip without panicking.
- `project`: the active tab renders as a pill carrying the loaded count; each empty
  state's text; the header row is present.
- `app`: `?` renders the legend containing every binding's help text and no binding
  in a group lacks one; at 80×24 the legend lays out two by two, and at 40×20 the
  last group is reachable by scrolling; `q` closes the legend, the log, the picker, and the confirm
  overlay and quits from a view; `i` opens a row; the status line shows the spinner
  glyph while a loader is in flight and the crumbs when it is not; a selected row
  carries the surface background sequence and the unselected one does not.
- `identity`: `Surface` for slot 0 in each tone against expected hex values.

## 12. Out of scope

Filed as ideas in `tui` when the plan lands: mouse support; sorting by column;
choosing and ordering columns from config; a configurable pane cap; animation
(harmonica) — nothing in a list of rows earns motion beyond the spinner.
